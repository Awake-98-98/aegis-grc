# M1 设计取舍：平台基座

本文记录 M1 阶段的关键决定与理由，供后续里程碑复用，避免同一问题反复讨论。

## 1. 为什么选择 FastAPI + SQLite + Jinja2

M1 的约束是"个人开发、单机运行、零外部服务、可离线"。三条候选路线：

| 方案 | 优点 | 放弃原因 |
|---|---|---|
| Django 全家桶 | 自带后台、ORM、迁移 | 依赖面大，后台形态与本产品信息架构不匹配，二次改造成本高 |
| Flask + 插件拼装 | 轻 | 认证、校验、OpenAPI 都要自己选型，长期一致性差 |
| **FastAPI + SQLAlchemy + Jinja2** | 类型化请求模型、自动 OpenAPI、依赖注入天然适合权限校验 | 无自带后台，需要自己写控制台（本阶段已接受） |

前端不引入 Node 构建链。咨询工作台的页面是表单与表格，服务端渲染足够，且打包后一个 Python 进程即可交付，避免"数据库 + 后端 + 前端"三段式部署。

## 2. 自研版本化迁移器，而非 Alembic

`aegis/db/migrator.py` 只做三件事：读 `aegis/db/migrations/` 下的模块、按版本号顺序执行、把已应用版本写入 `schema_migrations`。

理由：

- Alembic 的 autogenerate 依赖模型元数据，早期频繁改表时容易生成与手写并存的混乱迁移；
- 本产品只需要"前进式、幂等、可审计"的迁移，不需要 downgrade；
- 迁移模块是普通 Python 函数，可在测试里直接用内存库跑一遍，验证首次应用与二次幂等。

代价是必须手写 `upgrade(conn)`，但换来迁移内容可读、可评审、无隐藏状态。

## 3. 认证：不透明会话令牌 + scrypt

- **密码**：scrypt（N=2^14, r=8, p=1），存储格式 `scrypt$N$r$p$salt$hash`，参数随哈希一起存，未来可平滑升级。密码策略为 ≥10 位、含字母与数字、≤128 位。
- **会话**：登录生成 32 字节随机令牌，数据库只存 SHA-256 摘要与 CSRF 令牌，泄漏数据库也无法重放会话。
- **Cookie**：`HttpOnly`、`SameSite=Lax`、生产环境 `Secure`，路径 `/`。
- **Bearer 优先**：`aegis/api/deps.py` 的 `_extract_token` 先看 `Authorization`，再看 Cookie。这样脚本携带 Bearer 时不会被浏览器残留 Cookie 干扰，也避免"有 Cookie 就必须过 CSRF"的误伤。此决定由测试暴露：早期实现先读 Cookie，导致 Bearer 请求返回 403。

## 4. CSRF 与写操作的边界

Web 表单写操作校验 `csrf_token`；API 使用 Cookie 会话时校验 `X-CSRF-Token`；纯 Bearer 请求不需要 CSRF（令牌本身不随浏览器自动携带）。校验失败统一返回 `AEG-3004`。

## 5. 审计与业务写入同事务

`AuditService.record` 与业务变更共用同一个 `Session`，一次 `commit` 落库。理由：

- 若业务成功而审计失败，等于留下无法追责的变更；
- 若审计成功而业务回滚，审计表会出现"幽灵事件"。

审计事件 append-only，只提供查询接口，不提供修改与删除。每条事件记录 `actor_id`、`actor_email`、动作、实体类型/ID、变更前后快照、IP、UA、请求 ID。快照在服务层序列化，避免把 ORM 对象泄漏到审计层。

## 6. RBAC 放在服务层，而不是路由层

路由只负责解析参数与返回响应；权限判定在 `ServiceBase.require(actor, permission)`。理由：

- Web 与 REST 共用同一套规则，新增入口不会漏判；
- 测试可以直接构造 `AuthContext` 调服务层，无需起 HTTP；
- 将来加 CLI 批量导入时，权限模型仍然成立。

角色定义为三段：`admin` 持 `*`、`consultant` 持业务读写 + 审计只读、`viewer` 全只读。末位管理员保护：降级或停用最后一名管理员返回 `AEG-2002`。

## 7. 单进程内存限流

登录限流用模块级滑动窗口（`LOGIN_LIMITER`），按"IP + 邮箱"计数。选择内存而非 Redis/数据库：

- 单机部署下没有第二个进程，内存即全局；
- 避免为限流引入外部依赖或额外的写放大；
- 测试通过 `_reset_limiter` 保证用例间隔离。

已知局限：进程重启后计数清零；多进程部署时各进程独立。M6 运营化阶段若要横向扩展，再迁移到数据库计数。

## 8. 统一错误码

`aegis/errors.py` 定义 `ErrorCode`：

| 区间 | 含义 | 示例 |
|---|---|---|
| `AEG-1xxx` | 配置与启动 | `AEG-1001` 配置非法 |
| `AEG-2xxx` | 用户与会话 | `AEG-2001` 未认证、`AEG-2002` 末位管理员 |
| `AEG-3xxx` | 权限与输入 | `AEG-3001` 校验失败、`AEG-3004` CSRF |
| `AEG-4xxx` | 业务状态 | `AEG-4001` 非法状态流转 |
| `AEG-5xxx` | 基础设施 | `AEG-5001` 数据库错误 |

错误码稳定，前端与集成方可以按码分支处理，不依赖英文消息文本。

## 9. 数据模型的关键约束

- 客户编号 `CL-0001`、项目编号 `ENG-YYYY-####` 由服务层生成，唯一索引兜底；
- 项目必须挂在客户下，删除客户采用归档（`status=archived`）而非物理删除；
- 干系人随项目/客户级联删除，但审计事件保留；
- 所有时间存 naive UTC，序列化时补 `Z`，展示层再按本地时区格式化，避免 SQLite 时区语义不一致。

## 10. 已知边界（留给后续里程碑）

- 无附件存储（M4 证据管理时引入内容寻址存储）；
- 无全文检索（M2/M3 数据量上来后再评估 FTS5）；
- 无导入导出（M6）；
- 无备份/恢复脚本（M6）；
- 限流为单进程内存实现（见第 7 节）。
